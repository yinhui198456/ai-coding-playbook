# SOP · 目录规范与每周整理

> [!tip] 一句话
> 结构服务于"漏斗"：学习区 → 基础概念 → 案例 → 经验卡 → 方法论/SOP。新文件先进对的区，命名只用英文。

## 各区职责（新内容该进哪个区）

| 目录 | 收什么 | 不收什么 |
| --- | --- | --- |
| `learning/` | 学习队列、外部路标（链接+用途） | 外部资料正文 |
| `foundations/` | 术语、流程、工具的扫盲笔记 | 具体项目的踩坑（那是经验卡） |
| `cases/` | 一个 Issue 的 8 站全程纪实 | 提炼后的结论（复盘时升入经验卡） |
| `experience/` | AC 编号经验卡（踩坑→判断） | 未亲历的"听说" |
| `methodology/` | 多张经验卡重复验证后的方法论 | 📝 状态的草稿 |
| `sop/` | 可重复执行的流程检查单（本页即一例） | 一次性记录 |
| `retrospectives/` | 阶段复盘（按日期归档） | 进行中的案例（在 cases） |
| `templates/` | 模板（`draft: true`，不发布） | 正式内容 |

## 命名规则

1. **文件名只用英文小写 kebab-case**；中文标题写在 frontmatter 的 `title:` 里。
2. 案例页：`issue-<编号>-<英文短名>.md`，短名尽量和 TCP 分支名一致（如 `issue-194-member-core-flow` ↔ `feat/issue-194-member-core-flow`）。
3. 经验卡：`AC-<编号>-<英文短名>.md`，编号在 [[experience/index|经验卡索引]] 里登记。
4. 复盘：`YYYY-MM-DD-<主题英文>.md`。
5. 改名必须全库搜替换旧名（双链按文件名解析），改完跑 `npx quartz build` 验证。

## 每周卫生检查单（复盘时跑一遍，5 分钟）

- [ ] 新文件进对区了吗？命名合规吗？
- [ ] 有没有 📝 状态停滞超过两周的页面？（要么推进，要么写明卡住原因）
- [ ] 有没有没有出链的孤儿页？
- [ ] 案例页完结（站 8 验收完）了吗？完结算账：复盘手写区填了没、候选经验卡立项了没
- [ ] `npx quartz build` 通过，抽查新增链接可打开
