# 术语词典 · 人话版

> [!tip] 怎么用
> 不用一次背完。看经验卡或和 AI 对话时遇到生词，回来查。每个词都标了「我的坑位」——我在哪个真实事件里因为它吃过亏。

## AI 协作类

| 术语 | 人话解释 | 我的坑位 |
| --- | --- | --- |
| Agent（智能体） | 不只聊天，还能自己调用工具（读文件、跑命令、改代码）干活的 AI | [[AC-001-user-flow-first\|AC-001]]：没想清楚就让它干，它就替你乱决定 |
| Prompt（提示词） | 你给 AI 的任务说明书，写得多清楚，它就干得多准 | 贯穿所有经验卡 |
| Context（上下文） | AI 此刻"脑子里"能看到的全部信息：规则、代码、对话。塞乱了它就糊涂 | [[AC-003-stop-patching\|AC-003]]：规则、任务、临时状态混在一起出问题 |
| Token | AI 的"字数计量单位"，上下文和回答都按它算钱算容量 | 长对话变"健忘"往往就是上下文装满了 |
| 幻觉（Hallucination） | AI 一本正经地编造不存在的接口、文件或事实 | [[AC-002-test-vs-real-use\|AC-002]]：所以"它说完成"不算证据 |
| 一个写入者 | 同一时刻只让一个 Agent 改代码，其余只能看 | [[retrospectives/2026-08-16-tcp-phase-review\|阶段复盘]]：权限分层后混乱减少 |
| MCP（Model Context Protocol） | AI 调用外部工具（浏览器、数据库等）的通用插座协议 | TCP #184：Playwright MCP 让 Codex 能操作真实浏览器 |
| CLI | 命令行工具：在黑窗口里打字操作的程序（如 Claude Code、Codex CLI） | TCP #180：Codex CLI 角色边界 |

## 任务与代码管理类

| 术语 | 人话解释 | 我的坑位 |
| --- | --- | --- |
| Issue | 一张任务单：要做什么、为什么、怎么算完成 | [[AC-001-user-flow-first\|AC-001]]：Issue 字很多 ≠ 用户流程想清楚了 |
| PR（Pull Request） | 改完代码后提交的"合并申请单"，附说明，等人审查 | 经验卡里的 PR #179 / #182 |
| Draft PR | 草稿 PR：先开出来跑检查和讨论，明说"还不许合并" | TCP #71~#75 的 Draft 门禁链 |
| Commit（提交） | 一次代码存档，带一句说明。小步多次优于一次大改 | [[AC-003-stop-patching\|AC-003]]：反复打补丁产生大量重复提交 |
| 分支（Branch） | 从主线复制一条平行线改代码，改好再并回去，不干扰主线 | 本知识库就用 v5 分支建站 |
| Merge（合并） | 把分支的改动并入主线 | — |
| 合并冲突（Conflict） | 两边改了同一处，Git 不知道该听谁的，要人手工裁决 | ⚠️ 遇到就停下来，别让 AI 猜着解 |
| Code Review（代码审查） | 合并前由人（或另一个 AI）检查代码：逻辑对不对、有没有漏掉旧入口 | [[AC-003-stop-patching\|AC-003]]：只读审查发现了写入者没碰的旧接口 |

## Git 操作类

| 术语 | 人话解释 | 我的坑位 |
| --- | --- | --- |
| gh（GitHub CLI） | GitHub 官方命令行工具：在终端里直接管 Issue、PR、CI。git 管代码历史，gh 管平台上的协作 | 本机未安装时只能用 curl 调 API 代替；装好后 Agent 可直接做交付终态核对（TCP #185） |
| 暂存区（Staging） | 提交前的"打包区"，`git add` 把改动放进去 | [[foundations/git-basics\|Git 基础]] 旅程图 |
| origin / upstream | origin 是自己的远端仓库；upstream 是 fork 来源的官方仓库 | 本知识库的 Quartz 官方源就是 upstream |
| Stacked PR（堆叠 PR） | PR 的合并目标不是 master 而是另一条未合并分支，链条长了就没人说得清现状 | [[AC-004-confirm-branch-first\|AC-004]]：PR #179 活例 |
| Worktree（工作树） | 同一仓库开多个工作目录，各占一条分支，多 Agent 并行必备 | TCP #55；[[foundations/git-basics\|Git 基础]] |
| force push（强制推送） | 用本地历史覆盖远端历史，可能毁掉别人的工作 | 小白红线，AI 提出时必须人工确认 |
| detached HEAD | 没站在任何分支上的悬空状态，此时提交容易丢 | [[foundations/git-basics\|Git 基础]] 折叠区 |

## 验证与交付类

| 术语 | 人话解释 | 我的坑位 |
| --- | --- | --- |
| 单元测试 | 针对一个最小功能点的自动检查："输入这个，必须输出那个" | [[AC-002-test-vs-real-use\|AC-002]]：它只证明某个规则成立 |
| 集成测试 | 几个模块拼起来测："它们接得上吗" | TCP 后端 API 测试 |
| E2E 测试（端到端） | 模拟真人在浏览器里点完全流程 | TCP #1~#6 引入 Playwright 建的就是它 |
| 冒烟测试（Smoke Test） | 上线前最快过一遍"主功能没冒烟起火"的几条用例 | TCP #3 把旧脚本迁移为 Playwright 烟雾测试 |
| 视觉回归 | 自动对比页面截图，发现"长得和原来不一样"的改动 | TCP #4/#7~#10 的页面基线截图 |
| 测试金字塔 | 快又便宜的测试（单元）多做，慢又贵的（E2E）少做 | TCP `docs/05_Development.md` §2.3 |
| 回归测试 | 改动后重跑旧测试，确认没把以前能用的功能弄坏 | [[AC-002-test-vs-real-use\|AC-002]]：全量检查里的"历史失败" |
| 基线（Baseline） | "当前已知的正常状态"清单，用来区分新问题和老问题 | TCP #183：收敛 master 既有失败基线 |
| 质量门禁（Quality Gate） | 不达标就不许合并的自动检查关卡 | TCP #78：三个 workflow 的 CI 门禁 |
| UAT（用户验收测试） | 真人在真实页面上走一遍完整流程，确认真的能用 | [[AC-002-test-vs-real-use\|AC-002]]：这是唯一算数的最终证据 |
| 验收（Acceptance） | 对照最初需求逐条确认"做到了"，做到才算交付 | [[AC-002-test-vs-real-use\|AC-002]] |

## CI/CD 与发布类

| 术语 | 人话解释 | 我的坑位 |
| --- | --- | --- |
| CI（持续集成） | 每次提交后，机器自动跑构建和测试的"门卫" | TCP #78：堆叠 PR 曾绕过门卫，补了触发规则；[Actions 页](https://github.com/yinhui198456/team-capability-platform/actions)反复出现的运行记录就是它——push 一次触发一次，不用人点。实战见 [[cases/issue-194-member-core-flow\|#194 案例]] 站 5/6 |
| CD（持续交付/部署） | 通过门禁后，自动把版本送到可发布/已发布状态 | — |
| Workflow / Pipeline | 一条自动化流水线：拉代码 → 安装 → 测试 → 报告 | TCP `.github/workflows/` 下三个文件 |
| Artifact（构建产物） | 流水线跑完留下的东西：截图、报告、安装包 | Playwright 失败时的截图证据 |
| 构建（Build） | 把人写的源代码变成机器能跑的东西 | 本知识库 `npx quartz build` 就是构建 |
| 部署（Deploy） | 把构建好的东西放到服务器上跑起来 | TCP 用 Docker Compose 部署到 Ubuntu |
| 回滚（Rollback） | 新版本出事了，退回上一个能用的版本 | — |
| 种子数据（Seed） | 演示/测试用的初始数据，脚本一键灌入 | TCP PR #77：demo 账号种子必须外部给密码 |
| fail closed | 出问题时默认**拒绝**而不是放行（安全设计原则） | TCP PR #77：缺少种子密码时干脆不建账号 |

## 架构与代码类

| 术语 | 人话解释 | 我的坑位 |
| --- | --- | --- |
| 前端 / 后端 | 前端=用户看得见摸得着的界面；后端=在背后处理数据和规则的部分 | TCP：React 前端 + FastAPI 后端 |
| 技术栈 | 一个项目用了哪些技术的清单 | TCP 栈见 `docs/05_Development.md` |
| API（接口） | 前后端、模块之间约定好的"通话方式"：给什么参数、回什么结果 | [[AC-003-stop-patching\|AC-003]]：旧接口没退役，废弃流程死灰复燃 |
| 路由（Routing） | URL 和页面的对照表："/plan" 该显示哪个页面 | UAT 缺陷群 #132/#143：菜单和路由不一致 |
| 深链接（Deep Link） | 直接指向某个具体页面/状态的 URL，分享出去别人打开就是那一幕 | TCP #161：无效深链接静默显示错页面 |
| 状态机 | 一个东西能有哪几种状态、状态之间怎么跳的图纸 | UAT #113/#118/#144/#145：没图纸就自相矛盾 |
| 口径 | "同一个数字到底怎么算出来"的约定 | TCP #64 统一口径；#124：两处完成率 20% vs 22% |
| 快照 / 历史不可变 | 给某一刻的数据拍张照片存档，事后不许回去改历史 | TCP #57 设计门禁定义的规则 |
| 原子性 | 一批操作要么全成功，要么全失败，不许做一半 | TCP #82：自评提交与任务生成必须同生共死 |
| 幂等性 | 同一次操作重复发 N 次，效果和发一次一样 | TCP #82：重复点击不得生成重复任务 |
| DI（依赖注入） | 零件从外部递进来，而不是自己造——方便替换和测试。⚠️ 和 CI 只差一个字母，完全无关 | FastAPI 的 `Depends` 就是它 |
| 数据库迁移（Migration） | 改表结构的版本化脚本，能按顺序升级数据库 | TCP `backend/app/migrations` 有专属规则文件 |
| ORM | 用代码对象操作数据库，不用手写 SQL | TCP 后端用 SQLAlchemy |
| Lint / Linter / Formatter | Lint 是"挑毛病"这个动作：机器检查代码风格和低级写法；Linter 是干这活的工具，Formatter 是自动排版工（ESLint、Prettier、Ruff） | TCP 前后端各配了一套，CI 里自动跑 |
| 环境变量 | 不写进代码里的配置（密码、端口），运行时从外面传入 | TCP #55 用环境变量切换端口；PR #77 凭据只走环境变量 |
| Docker / 容器 / 镜像 | 把程序连运行环境打包成一个标准箱子，到哪都能跑 | TCP compose.yaml 编排前端、后端、数据库 |
| MVP（最小可行产品） | 只做最核心功能、先能跑起来验证的版本 | TCP 05 文档全程按 MVP 边界设计 |
| 领域模型 | 业务里有哪些概念、什么关系的一张图 | TCP #57：先统一领域模型才许动代码 |
| 设计门禁 | 设计未定稿之前，不许开始写代码的规则 | TCP #57 就是这个门禁本身 |

## 问题与维护类

| 术语 | 人话解释 | 我的坑位 |
| --- | --- | --- |
| 技术债 | 图快留下的隐患，像借钱：现在省事，以后连本带利还 | [[AC-003-stop-patching\|AC-003]]：逐个打补丁就是在还利息 |
| 打补丁（Hotfix） | 只修眼前这一处的最小修改；快，但不查根因 | [[AC-003-stop-patching\|AC-003]]：同类问题第二次出现就要停手 |
| 重构（Refactor） | 不改功能，只把代码内部理顺，让它更好改、更不易错 | TCP R1~R4 就是分轮重构 |
| 接口退役 | 旧 API 正式下线，不许再能调用 | [[AC-003-stop-patching\|AC-003]]：旧 submit 接口没退役引发的问题 |
